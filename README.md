# QIP 2005 Jimm

Версия сопровождения **1.1.0** добавляет Launcher и отдельный QIP Update Agent. Исполняемые файлы классического клиента, скины, русский язык, звуки и настройки `icq.jimm.online:5190` остаются прежними.

Репозиторий содержит наш код и документацию. Файлы QIP в него не включены: разрешение на распространение оригинальной и модифицированной сборки пока не подтверждено. Локальный кандидат установщика подготовлен отдельно; публичная публикация полного дистрибутива заблокирована в workflow.

## Как работают обновления

Обычные ярлыки открывают `QipLauncher.exe`. Он запускает `qip.exe` с прежним рабочим каталогом и отдельно запускает обновлятор. Проверка сети не удерживает запуск клиента. При прямом запуске `qip.exe` Launcher обходится.

Обновлятор запрашивает анонимный GitHub API:

```text
https://api.github.com/repos/kappapr1der/qip2005-jimm/releases/latest
```

Во время работы клиента автоматическая проверка выполняется не чаще раза в 24 часа, включая неудачные попытки. Новая стабильная версия скачивается автоматически. Перед установкой обязательны подпись RSA-3072/SHA-256 доверенным ключом и SHA-256 установщика. Старая версия, неправильный репозиторий, неподписанный манифест и повреждённый файл не допускаются к установке.

По умолчанию появляется запрос установки. Можно отдельно включить установку после закрытия QIP. Обновлятор не завершает клиент и не прерывает переписку. Перед заменой файлов он копирует приложение, профили, историю и сведения удаления. При ошибке установки или проверки новых файлов восстанавливается предыдущая копия. Ошибочная версия больше не устанавливается автоматически до следующего релиза; ручной повтор возможен.

Worker выполняется из отдельного каталога пользователя. Работающий EXE обновлятора не перезаписывается. Незавершённая транзакция восстанавливается при следующем запуске Launcher. Резервные копии сохраняются; автоматического удаления старой истории нет.

В меню «Пуск» есть «Настройки обновлений». Там можно отключить автоматические проверки, включить автоматическую установку, проверить релиз вручную и указать дополнительную папку истории вне `Users`.

Данные агента: `%LOCALAPPDATA%\QIP2005\UpdateAgent`. Журнал содержит время Unix UTC и короткие коды ошибок, без содержимого переписки, профилей и токенов. При обычном удалении клиентских данных и резервных копий ничего не очищается. Отдельное согласие на полное удаление охватывает и резервные копии агента.

## Сборка

Цель: Windows 11 x64. Обновлятор написан на C++20/Win32, использует системные WinHTTP и BCrypt и статически подключённый runtime MinGW-w64. Пользователю не требуется устанавливать .NET, Python, Java или Visual C++ Redistributable. Python нужен только разработчику для тестов и подписания релизов.

```powershell
python -m pip install -r scripts/requirements-ci.txt
.\scripts\build-agent.ps1 -ToolchainBin C:\tools\w64devkit\bin
.\scripts\test.ps1 -ToolchainBin C:\tools\w64devkit\bin
```

Полный установщик требует законно полученного **чистого** пакета в `private/payload`, официального Inno Setup 6.7.3 и ключа подписи, совпадающего с публичным ключом проекта. `verify_payload.py` откажет при появлении дополнительных файлов или каталогов, включая аккаунты.

```powershell
.\scripts\build-installer.ps1 -ISCC 'C:\tools\Inno Setup 6\ISCC.exe' -SigningKeyDpapi 'C:\private\release-signing-key.dpapi'
```

`private`, `build`, `dist`, профили, история и секреты исключены из Git. Публичная часть ключа находится в `updater/keys/release-public.pem`. Созданный для этой локальной сборки секрет хранится отдельно, защищён DPAPI исходного пользователя Windows; он не включён в установщик, исходный архив и Git.
