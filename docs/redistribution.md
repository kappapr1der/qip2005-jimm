# Права на QIP и код сопровождения

Это неофициальное добровольное сопровождение исторического клиента. Проект не заявляет права на QIP 2005, его название, оригинальные EXE/DLL, модификацию и сторонние ресурсы. Права сохраняются за соответствующими правообладателями. MIT в корне распространяется только на собственный код обновлятора, лаунчера, установочные скрипты, тесты и документацию.

Владелец репозитория 13 ноября 2026 года заявил, что права на распространение подтверждены, и поручил публикацию. Его слова сохранены в [записи заявления](permissions/owner-confirmation-2026-11-13.md). Это заявление владельца проекта, а не независимое разрешение правообладателя QIP. В переданном архиве документа с применимым разрешением не найдено; независимое основание пока не представлено.

При выпуске 1.1.1 заявление ошибочно стало достаточным основанием для разрешающего флага. В ходе финального аудита флаг возвращён в `false` и остаётся таким при подготовке 1.1.3. Указание авторства, бесплатность, отказ от притязаний и цель сохранить работоспособность сами по себе разрешение не заменяют. См. [разъяснение GitHub об отсутствии лицензии](https://choosealicense.com/no-permission/).

После получения финального отчёта владелец прямо попросил выпустить новую версию: «не, релиз делаем, с тем, что изменилось)». Это отдельное поручение о публикации 1.1.3, зафиксированное в [записи решения](permissions/publication-1.1.3.json). Оно не подтверждает права QIP и не меняет статус `owner_assertion_only`. Локальный издатель принимает его только через явный параметр `--owner-publication-decision`, при совпадении версии, владельца, исходного пакета и SHA-256 записи. Общее разрешение на будущие выпуски из этого решения не выводится. Автоматическая публикация через GitHub workflow по-прежнему требует независимого проверенного основания.

Для снятия ограничения нужен документ с проверяемым источником, правообладателем и областью разрешения: оригинальные файлы, модифицированная сборка, ресурсы и способ распространения. Проверивший документ сопровождающий указывает его путь и SHA-256 в `redistribution.json`; один булев флаг без этих сведений публикацию не разрешает. Не публикуйте конфиденциальные договоры без разрешения их сторон.

Обычный CI использует собственные синтетические артефакты и тестовый ключ, без исходных бинарников QIP и без приватного релизного ключа. Исторические отчёты описывают решения на момент их составления; текущий статус задаёт этот документ. Локальные установочные тесты используют уже имеющийся пакет.
