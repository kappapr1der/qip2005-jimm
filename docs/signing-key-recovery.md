# Резервная копия ключа подписи

Релизный RSA-3072 ключ остаётся на компьютере сопровождающего. Приложение содержит только публичный ключ. Скрипты публикации не передают приватный ключ в GitHub; экспорт в GitHub Secrets удалён, сборка с подписью требует явного локального пути `-SigningKeyDpapi`.

Проверенная 13 ноября 2026 года схема: исходный DPAPI-файл вне Git и вторая DPAPI-копия в `%LOCALAPPDATA%\QIP2005-Maintainer\SigningKeyBackup`. ACL обеих копий разрешает доступ только текущему владельцу, SYSTEM и администраторам. Резервная копия расшифрована в памяти, ею подписаны случайные пробные данные, подпись проверена закреплённым публичным ключом. Изменённый DPAPI-файл отвергнут. Открытый ключевой файл на диск не записывался. Отчёт содержит только отпечаток публичного ключа и результаты проверок.

Повторная проверка с созданием новой копии:

```powershell
python scripts/backup-signing-key.py --source C:\private\release-signing-key.dpapi --destination "$env:LOCALAPPDATA\QIP2005-Maintainer\SigningKeyBackup\release-key-NEWDATE.dpapi" --report C:\private\key-backup-check.json
```

Существующую копию скрипт не перезаписывает. Не указывайте в качестве каталога назначения общую папку: скрипт ограничивает ACL именно этого каталога. Файлы ключа запрещены проверкой репозитория и исключены из Git; они также не входят в исходный ZIP или комплект на рабочем столе.

Это локальная защита от случайной потери одного файла, а не проверенное аварийное восстановление на новом компьютере. DPAPI обычно привязан к учётной записи и компьютеру; [описание Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata). Обе текущие копии находятся на системном диске. Восстановление после потери Windows, диска или учётной записи не проверялось. Доступ от имени того же пользователя и доверенный администратор не входят в защиту от компрометации.

До смены компьютера нужен отдельный переносимый архив: PKCS#8 с шифрованием и сильной парольной фразой, введённой локально, либо эквивалентный защищённый носитель. Хранить носитель и пароль отдельно, вне GitHub и облачной синхронизации. На запасной машине проверить подпись пробных данных существующим ключом и соответствие публичному отпечатку. Носитель и пароль владелец ещё не выбрал; такое восстановление не объявляется выполненным.

Если ключ потерян окончательно, новый публичный ключ не становится доверенным для старых агентов автоматически. Нужна явно проверяемая миграция доверия или ручная установка; отключать проверку RSA для восстановления обновлений нельзя.
