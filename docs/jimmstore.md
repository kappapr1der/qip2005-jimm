## Что указано

Название — QIP 2005 Jimm, сопровождающий — kappapr1der, платформа — Windows, категория — `client` (официальное значение «Клиент»). Описание перечисляет существующие возможности сборки. Сопровождение не приписано авторам оригинального клиента.

Обязательная иконка — исходный ресурс QIP, преобразованный в PNG 128×128. Происхождение и хеши описаны в [`assets/jimmstore`](../assets/jimmstore). Скриншоты необязательны и не добавлены. Поле лицензии также необязательно: MIT распространяется на собственный код сопровождения, а не на весь QIP, поэтому сборка не обозначена как open source.

Прямых ссылок на дистрибутив и упоминаний форматов исполняемых файлов или архивов в манифесте нет: документация магазина запрещает их. Ссылки на сайт и автора ведут на страницы GitHub.

## Версия и последующие выпуски

В официальном формате нет поля версии приложения или отдельного URL релиза. Их добавление нарушило бы `additionalProperties: false`. Вместо них указан источник:

```json
{"type": "github", "repo": "kappapr1der/qip2005-jimm"}
```

JimmStore сам получает версию из GitHub Releases и направляет кнопку скачивания на [страницу последнего релиза](https://github.com/kappapr1der/qip2005-jimm/releases/latest). По документации сведения обновляются примерно раз в час. Переписывать манифест или выдавать приложению GitHub-токен для этого не нужно.

На момент подготовки `VERSION` и текущий стабильный GitHub Release соответствуют 1.1.3. При следующем выпуске обычный процесс проекта синхронизирует `VERSION` и тег `vX.Y.Z`; workflow `JimmStore manifest` проверяет соответствие при событии `release: published`. Он не создаёт релизы и не отправляет заявки. Проверка PR допускает подготовку новой версии до её публикации.

## Проверка

Python 3.12:

```powershell
python -m pip install -r scripts/requirements-store.txt
python scripts/validate_jimmstore.py --fetch-schema --report build/jimmstore/validation.json
python -m unittest discover -s tests -p test_jimmstore.py -v
```

После размещения файлов в `main` можно дополнительно проверить публичные URL и текущий релиз:

```powershell
python scripts/validate_jimmstore.py --fetch-schema --check-public --check-latest
```

Проверяются официальная схема и URI-форматы, дополнительные запреты документации, соответствие репозиторию, размер и формат настоящей иконки. Публичная проверка сравнивает скачанные JSON и PNG с локальными файлами. Ни одна команда не отправляет данные в форму магазина.

CI запускает эту проверку и контрактные тесты при изменениях манифеста, ресурсов, проверяющего кода и версии. Изменившаяся схема требует ручного пересмотра контрольной суммы и тестов. Успешный CI не заменяет серверную проверку формы и модерацию JimmStore.

## Как отправить

1. Войдите в свой аккаунт на [странице отправки](https://jimm.online/store/submit).
2. В поле «Ссылка на jimm-app.json или на репозиторий» вставьте:

   ```text
   https://raw.githubusercontent.com/kappapr1der/qip2005-jimm/main/jimm-app.json
   ```

3. Отметьте подтверждение «Я автор приложения или представляю его. Ссылки ведут только на магазины или GitHub, без файлов», выступая как сопровождающий сборки.
4. Нажмите «Проверить и отправить». Исправьте возможные сообщения формы и дождитесь решения модератора.

Автоматическая отправка заявки не выполнялась. Изменение названия, id и ссылок уже опубликованного приложения, по документации магазина, требует новой проверки модератором.
