# Сквозная проверка подписанного обновления

```powershell
python tests/test_e2e_update.py --toolchain C:\tools\w64devkit\bin --iscc C:\tools\inno\ISCC.exe --work C:\private\qip-e2e-NEW --report C:\private\qip-e2e-results.json
```

Рабочий каталог должен быть новым. Тест не использует исходный QIP, пользовательские данные, GitHub-токен или релизный приватный ключ. Создаётся временный RSA-3072 ключ в памяти; в тестовый native EXE включается только его публичная часть. Python обслуживает синтетические ответы API и подписанные артефакты на `127.0.0.1` со случайным портом. Данные подписываются как точные байты RSA/PKCS#1 v1.5 с SHA-256; проверяет их тот же native BCrypt-код, который используется в приложении.

Отдельная копия дерева исходников получает тестовые AppId и имена ярлыков. В ней компилируется `tests/e2e_driver.cpp`, который вызывает настоящие `checkCycle`, `stageWorker`, `worker`, `recoverPending`, `WindowsInstaller`, `Snapshot` и проверку установленных файлов. Рабочий процесс действительно копируется вне каталога приложения и запускается отдельным процессом. Установщики двух версий собираются настоящим Inno Setup, содержат собственный управляемый процесс под именем qip.exe, инертный тестовый docking.dll и два тестовых агента. Оригинальные файлы клиента не нужны.

Проверяются ожидание закрытия процесса без его принудительного завершения, переход 1.1.1 → текущий VERSION (для этого выпуска 1.1.2), точное сохранение тестовой истории, снимок до установки, равенство версий, понижение версии, повторный запуск без второй копии, подготовка HistPath/Startup, совместимость с опубликованной логикой рабочего процесса 1.1.1 и возвращение ненулевого кода при ошибке помощника. Отдельный установщик намеренно повреждает только тестовую историю и завершается с кодом 42; рабочий процесс восстанавливает программу, данные и регистрацию. Сценарий незавершённого журнала запускает настоящий путь восстановления. Повреждённый установщик, чужая подпись, недоступное API и попытка передачи подготовки профиля без подписанного активного задания отвергаются.

Общий фрагмент `installer/profile-finalization.iss` включается и в настоящий установщик, и в синтетические установщики. Замороженный `tests/fixtures/v1.1.1/main.cpp` проверяет совместимость нового помощника с прежним рабочим процессом. Он компилируется с текущими совместимыми нижележащими заголовками; это проверка старой логики, а не запуск неизменённого опубликованного EXE. Отдельный живой аудит проверял именно неизменённый агент 1.1.0 и настоящий релиз 1.1.1 через GitHub.

Тестовый HTTP-адаптер существует только в тестовой точке входа. В поставляемом EXE нет переключателя на локальный сервер или ключ из переменной окружения. Производственный HTTPS, сертификаты и перенаправления GitHub проверяются отдельно реальным сетевым тестом. Сквозной тест не проверяет настоящую авторизацию, отправку сообщений, звуки или физическое отключение питания. Созданные тестовые данные остаются в указанном рабочем каталоге; завершающий шаг удаляет только свою временную регистрацию приложения.

CI запускает этот тест при PR и push без ключа подписи релизов и без бинарников QIP. У обычного job только `contents: read`. Получение исходного QIP-пакета отдельно закрыто проверкой прав; синтетический сквозной тест выполняется независимо от неё.
