# Устройство обновлений

`QipLauncher.exe` и `QipUpdateAgent.exe` — две точки входа одного нативного EXE. Launcher проверяет наличие незавершённой транзакции, запускает оригинальный клиент через `CreateProcessW` с `{app}` как рабочим каталогом и создаёт отдельный процесс мониторинга. Запросов HTTP в этом пути Launcher нет.

Монитор живёт во время работы QIP, проверяет срок следующего запроса через каждые 30 секунд и прекращает работу после выхода клиента. Мьютекс исключает одновременные мониторы одной установки. Настройка `check_automatically=false` отключает автоматические запросы; ручная проверка по кнопке остаётся доступной.

GitHub API используется без Authorization и токенов. TLS-сертификаты проверяет Windows. Перенаправления проходят только по HTTPS на GitHub и его фиксированные домены доставки; автоматическое произвольное перенаправление выключено. Тайм-ауты и размеры ответов ограничены. URL установщика привязан к репозиторию, тегу и имени подписанного артефакта.

Манифест подписывается RSA-3072, PKCS#1 v1.5, SHA-256. Публичный модуль встроен в EXE. Проверяется подпись исходных байтов до разбора метаданных, затем репозиторий, SemVer, дата, имя установщика, размер, SHA-256 и список файлов. Манифест действует 180 дней. Установленные и уже аутентифицированные более новые версии защищают от отката. Путь `Users`, изменяемые CFG и обходы каталогов запрещены в списке заменяемых файлов. Хэши `qip.exe` и `docking.dll` закреплены отдельно.

После согласия или включённого автоматического режима агент копирует себя в `%LOCALAPPDATA%\QIP2005\UpdateAgent\transactions\{id}\QipUpdateWorker.exe` и завершает свой процесс из папки приложения. Worker берёт блокировку установки и ожидает выхода QIP, Launcher и открытых окон агента этой установки. Прямой повторный запуск Launcher во время обновления сообщает об ожидании; активный клиент не завершается.

Снимок содержит все файлы приложения, `Users`, выбранную внешнюю папку истории, точный набор значений собственного ключа удаления HKCU и существующие собственные ярлыки. Переходы через reparse points запрещены. Каталог резервной копии не может лежать внутри копируемого дерева. Проверяются контрольные суммы скопированных файлов. Содержимое и имена личных файлов не записываются в журнал.

Перед запуском установщика SHA-256 проверяется повторно, а файл удерживается дескриптором без разрешения записи. Inno Setup работает в тихом пользовательском режиме с `/NORESTART`. Его собственная проверка процессов повторно блокирует занятую установку, без Restart Manager и принудительного закрытия клиента. После завершения проверяются версия и все подписанные программные файлы.

Если процесс установки вернул ошибку или новые файлы не совпали, снимок восстанавливает старые файлы, данные, ключ удаления и ярлыки. Маркеры `installing`/`restoring` позволяют продолжить восстановление после обрыва. Если файловая система не позволяет восстановление, копия и маркер остаются: автоматическое продолжение не выдаёт этот случай за успех.

Перед ручной установкой поверх имеющегося QIP Inno извлекает наш helper в временную папку. Helper создаёт полный снимок и сохраняет `QipRecovery.exe` рядом с ним. Восстановление вручную, при закрытом QIP:

```powershell
.\QipRecovery.exe --restore-backup "$env:LOCALAPPDATA\Programs\QIP2005" manual-ID_ИЗ_ИМЕНИ_ПАПКИ
```

Дополнительная папка истории задаётся пользователем явно. Корень диска, системная папка, каталог агента, их рекурсивное включение и ссылки не принимаются. Перед первой ручной установкой 1.1.0 история, сохранённая вне стандартного `Users`, должна быть скопирована пользователем отдельно, если её путь ещё не указан в настройках агента.

Сохранённые копии содержат личные данные. Они остаются в профиле текущего пользователя и не загружаются в GitHub. Автоматическая очистка копий не включена. Полная очистка деинсталлятором требует отдельного согласия и охватывает `Users`, четыре CFG и каталог данных агента; внешняя история не удаляется.
